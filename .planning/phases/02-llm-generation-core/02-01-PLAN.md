<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pasted JD/objective text → LLM | Untrusted user input crosses into the model context (prompt injection vector) |
| OpenRouter response → backend | Untrusted LLM output enters the app (validation boundary) |
| Backend → logs/runs.jsonl | Data written to disk that must never contain secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering/Elevation | gateway user message (pasted JD) | medium | mitigate | JD/objective is data in the USER message, never system (D-07); system prompt declares facts-only; output is Pydantic-validated and never executed — worst case is a failed validation contained by the retry cap (D-04) |
| T-02-02 | Information Disclosure | llm/logging.py runs.jsonl | high | mitigate | Log metadata only (tokens/cost/latency/status) — never OPENROUTER_API_KEY, full prompts, or responses; logs/ gitignored in Task 1 before any writer runs (Pitfall 8) |
| T-02-03 | Tampering | gateway OpenRouter response | high | mitigate | Every response re-validated with strict Pydantic (extra="forbid") regardless of wire `strict: true` — per-provider enforcement varies (RESEARCH Pattern 2); invalid content raises, never returns downstream (SC3) |
| T-02-04 | DoS (wallet) | gateway call loop | medium | mitigate | max_tokens from PromptSpec + LLM_MAX_ATTEMPTS=3 in config (D-04); no unbounded runs; default test suite offline (D-16) |
| T-02-SC | Supply Chain | uv add openai | high | mitigate | Package Legitimacy Audit in 02-RESEARCH.md: official openai/openai-python repo, referenced by OpenRouter docs — approved, SUS verdict judged false positive; no blocking checkpoint required |
</threat_model>
