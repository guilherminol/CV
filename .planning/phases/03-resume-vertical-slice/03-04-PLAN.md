<planner_decisions>
- Default landing view is Currículo (nav order lists it first; it is the phase's core flow) — Perfil remains one click away. Planner discretion per CONTEXT.md; trivially reversible.
- Pre-generate keyword arrival = debounced auto-extraction (research Open Question 2 recommendation): the lint query fires when the DEBOUNCED (800ms) JD reaches 80 trimmed chars — one real LLM call per settled state, never per keystroke.
- Per-stage cycling labels (Zone 3 optional tier) are NOT built — the single in-flight hint line is the spec's stated minimum contract; the single POST returns once.
- The lint panel shows one combined state (backend returns profile-only + keyword-gap checks together): while the query is pending the panel area stays empty (form remains the anchor); on arrival it renders warnings or the clear-line.
- The keyword chip status text ('no currículo' / 'ausente') renders as visually-hidden text inside each chip so status is never conveyed by glyph/color alone (accessibility baseline).
</planner_decisions>
