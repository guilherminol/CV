# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 utility components (established in Phase 1) |
| Icon library | none — unicode text glyphs only (✓ ⚠ ○), always `aria-hidden` and paired with a text label |
| Font | System UI stack (Tailwind default; no custom font loaded) |

**Decision (auto mode, recommended option):** do not introduce shadcn/radix. Grounded in locked upstream constraints: STACK.md pins a deliberately lean stack (native fetch, no i18n framework, no extra UI deps), and Phase 1 already shipped a coherent hand-rolled component set (`CompletenessGrid`, `ErrorPanel`, `PlaceholderBanner`, `ProfilePreview`) on plain Tailwind v4. CONTEXT.md D-05 explicitly builds the result screen on the ProfilePreview visual base — a component library would diverge from it. All UI strings are PT-BR, centralized in `frontend/src/constants/ui.ts` (established pattern; no i18n framework).

**Panels, not modals:** no modal dialogs and no toast system in this phase. Every state (lint, error, ephemeral notice, coverage) renders as an inline panel in the page flow, mirroring the shipped ErrorPanel/PlaceholderBanner pattern.

## Screen Structure & Interaction Flow

Single screen ("Currículo"), enabled by flipping the nav flag: `NAV_ITEMS` → `{ id: 'curriculo', enabled: true }` in `frontend/src/constants/ui.ts`. Layout follows the app shell: `max-w-3xl mx-auto px-4`, zones stacked with `space-y-6`.

**Profile gate.** The screen reuses the existing `['perfil']` React Query. Profile `status: 'erro'` → render the established `StatusLine` + `ErrorPanel` verbatim pattern (generation is unavailable until the profile loads). Profile ok → render the form. The `exemplo` placeholder banner (if present) still renders — reuse as-is.

**Zone 1 — Form card** (white card: `rounded-md border border-gray-200 bg-white shadow-sm p-4`):
JD textarea → language segmented control → primary CTA. CTA is disabled while the JD trims to fewer than 80 characters; the hint below the textarea explains why.

**Zone 2 — Completeness lint** (PROFILE-02; non-blocking per D-03). Renders once the JD reaches 80 characters. Split per D-04: profile-only checks (experiences without metrics; missing summary) render instantly; the JD-keyword-gap check populates when keywords arrive (it depends on extraction). Zero warnings → green clear-line. Warnings never block the CTA.

**Zone 3 — In-flight.** CTA disabled, label swaps to "Gerando currículo…"; a status region under the form shows the in-flight hint. If the orchestrator exposes per-stage feedback (D-01: three sequential stage calls), the status line cycles "Gerando resumo…" → "Gerando experiências…" → "Gerando habilidades…"; otherwise the single line stands. Both satisfy this contract; minimum is the single line.

**Zone 4 — Result ("Currículo gerado")** (D-05). Resume-style card reusing the ProfilePreview patterns and section order (resumo, experiência, formação, habilidades, certificações, idiomas, projetos). The 3 generated sections each carry a **Gerado** badge; passthrough sections (formação, certificações, idiomas, projetos + contato/name header) each carry a **Do perfil** badge. Directly above the card: the neutral ephemeral notice (D-06). Card header row holds the secondary **Gerar novamente** button (re-runs with current inputs; replaces the ephemeral result without confirmation — deliberate, see Copywriting).
Language note: when the run language is `en`, localized passthrough fields render their `en` value when present, falling back to `pt-BR` (schema-guaranteed base) — extends the Phase 1 D-04 display convention to the chosen run language. Generated sections are already in the run language.

**Zone 5 — Keywords & coverage** (RESUME-02 + RESUME-04, one honest panel). Below the result card. Summary line first, then keywords grouped by the four fixed schema categories (Phase 2 D-10) in fixed order — Competências, Ferramentas, Títulos de vaga, Certificações — as wrapping chips; covered keywords carry ✓ (green), absent carry ○ (gray). Categories with zero keywords are hidden. Keyword display text uses the run-language field (`pt` for a PT-BR run, `en` for an EN run), per D-02.

**State machine:** `idle` (form only) → typing (lint panel appears ≥80 chars) → `in-flight` (controls locked) → `result` (zones 4–5 render; form stays at top for edits). Page refresh returns to `idle` — generated content is session-only (D-06), stated in the ephemeral notice.

**Visual anchor per state** (Dimension 2): `idle` — the form card is the anchor, with the accent CTA as its focal point; `in-flight` — the form card with the in-flight status line under it; `result` — the result card ("Currículo gerado") is the anchor, with the Gerado-badged generated sections as the emphasized content; zones 4–5 stack below it in reading order.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`, `py-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `px-2`, `py-2`) |
| md | 16px | Default element spacing, card padding (`gap-4`, `p-4`, `space-y-4`) |
| lg | 24px | Section padding, zone stacking (`px-6`, `space-y-6`) |
| xl | 32px | Layout gaps (`p-8`) |
| 2xl | 48px | Major section breaks (`py-12`) |
| 3xl | 64px | Page-level spacing (`py-16`) |

Exceptions: 12px (`px-3`, `gap-3`) and 20px (`py-5`, `p-5`) are permitted — both multiples of 4, already shipped in Phase 1 components (`ProfilePreview` card `px-6 py-5`, `CompletenessGrid` cells `px-3 py-2`, control padding `px-3 py-2`). Page frame stays `max-w-3xl mx-auto px-4` (Phase 1 shell).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 (`leading-[1.5]` on prose; textarea uses `leading-6` for input comfort) |
| Label | 12px (`text-xs`) | 400 | 1.5 (Tailwind default) |
| Heading | 16px (`text-base`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) |
| Display | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) |

Exactly 4 sizes (12/14/16/20) and 2 weights (400/600) for all new Phase 3 UI.

**Grandfathered Phase 1 patterns** (reused verbatim per D-05 — intentional consistency, not drift; do not "fix" them): `ProfilePreview` name `text-2xl font-bold`, section headings `text-sm font-bold uppercase`, emphasis `font-medium` (500), and the app header `text-lg font-bold`. New Phase 3 components outside the result card use only the contract values above.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fafb` (gray-50) | Page background (`bg-gray-50`) |
| Secondary (30%) | `#ffffff` (white) + `#e5e7eb` (gray-200) borders | Cards, header bar, form card, result card |
| Accent (10%) | `#2563eb` (blue-600) | Primary CTA, active nav item, focus rings, Gerado badge |
| Success | `#15803d` (green-700) on `#f0fdf4` (green-50) | Covered keyword chips, lint clear-line (mirrors CompletenessGrid present state) |
| Warning | amber family (amber-300 border / amber-50 bg / amber-900 text) | Lint warnings only — non-blocking attention (D-03) |
| Destructive / error | `#b91c1c` (red-700) on `#fef2f2` (red-50), border red-300 | Error panels only (ErrorPanel pattern) |

Text hierarchy: `text-gray-900` primary, `text-gray-700`/`text-gray-600` secondary, `text-gray-500` muted, `text-gray-400` disabled/placeholder (all as shipped in Phase 1).

Accent reserved for: the "Gerar currículo" primary button, the enabled "Currículo" nav item, focus-visible rings, the "Gerado" badge (marks what this phase produces, per D-05's "geradas em destaque"), and the selected option of the language segmented control (selected-state indication, per Component conventions). Never used for coverage status, lint, or error states — those have their own semantic colors. There are no destructive actions in this phase, so red is reserved exclusively for failure states.

| empty | Lint panel (list-collection) | ✅ covered | Zero warnings render the green clear-line "Nenhum gap relevante encontrado para esta vaga." |

| error | Currículo screen gate (nav) | ✅ covered | Broken profile renders the established StatusLine + ErrorPanel verbatim pattern; generation unavailable |
| error | Result zone (media) | ✅ covered | Red panel "Não foi possível gerar o currículo" + retry hint; any prior result stays on screen — failure never blanks the page |

| zero-one-many | Coverage summary (list-collection) | ✅ covered | Singular/plural copy "1 de 1 keyword" vs "{n} de {m} keywords" via a pure copy function (unit-testable offline, project test policy) |
| populated | Coverage at high volume (list-collection) | ✅ covered | 30+ keywords across 4 categories still render as a wrapping chip grid — never a table, never scroll |
| overflow | Coverage at high volume (list-collection) | 🧪 backstop | Visual check at verify: a JD rich enough to yield 30+ keywords keeps the panel readable (wraps, groups visible, no cramping) |
