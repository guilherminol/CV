## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request body → ExportarRequest | JSON body parsed into strict Pydantic models (localhost client, but the boundary is enforced anyway) |
| Gate verdict → response bytes | Bytes may only cross to the client after the gate passes — the delivery decision is in this plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-02 | Denial of Service | ExportarRequest size | medium | mitigate | strict extra=forbid model with Field bounds on every section (min_length=1 floors, max_length caps on resumo; section lists self-bound to resume size at personal scale) — mirrors the JD_MAX_LENGTH precedent |
| T-04-03 | Information Disclosure | error envelopes | medium | mitigate | house envelope split: PT-BR lines to the client, raw extracted text + exception detail to logger.error only; pinned by the caplog test |
| T-04-04 | Tampering | bytes delivered despite gate failure | high | mitigate | the route returns bytes ONLY on the gate-ok path; the gate-failure test asserts no PDF key in the erro body — ordering enforced by code shape + test (D-07/D-08) |
| T-04-05 | Denial of Service | base64 response size | low | accept | single-user localhost; a resume PDF is ~30-60KB (~80KB base64) — far under any header/body limits; the research evaluated raw-bytes vs envelope and chose the envelope deliberately |
</threat_model>
