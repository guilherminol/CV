# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 utility components (established Phase 1, extended Phase 3) |
| Icon library | none — unicode text glyphs only (✓ ✗ ○ ⚠), always `aria-hidden` and paired with a text label |
| Font | System UI stack (Tailwind default; no custom font loaded) |

**Decision (auto mode, recommended option):** do not introduce shadcn/radix. The Phase 3 approved UI-SPEC resolved this exact gate with a documented rationale — STACK.md pins a deliberately lean stack (native fetch, no extra UI deps) and the app already ships a coherent hand-rolled component set (`ResumeResult`, `KeywordsPanel`, `ErrorPanel`, `StatusLine`) on plain Tailwind v4. Phase 4 adds two blocks (export control + self-check panel) to an existing screen; a component library would diverge from the established visual base for zero gain. This phase re-affirms the Phase 3 decision rather than re-asking it.

**Panels, not modals:** no modal dialogs and no toast system. Export feedback (success receipt, self-check panel, gate failure) renders as inline blocks in the page flow — the established pattern. The PDF download itself is the browser's native download UI (D-11), not an in-app surface.

## Screen Structure & Interaction Flow

No new screen and no nav change. Phase 4 inserts **Zone 6 — Export + Self-check** into the existing Currículo result state, directly **below the result card (`ResumeResult`) and above the keywords/coverage panel (Zone 5)** — D-09 pins the primary CTA "abaixo do currículo montado": the export action belongs to the artifact it exports, and the proof block (export → self-check) reads as one unit. Page frame stays `max-w-3xl mx-auto px-4`; Zone 6 stacks with the existing `space-y-6` rhythm.

**Zone 6 composition (top to bottom):**

1. **Primary CTA — "Exportar PDF"** (D-09). Reuses the pinned primary-button classes verbatim (blue-600). A muted caption under the button sets the expectation that the self-check is automatic (D-13) and the download just happens (D-11): "O download começa automaticamente após a verificação ATS do arquivo." No language selector (D-12 — the PDF follows the run language), no separate self-check button (D-13).
2. **Export in-flight hint** — in the existing `aria-live="polite"` region (Zones 3/4/5 wrapper): "Renderizando o PDF e executando a verificação ATS…". While pending: CTA label swaps to "Exportando PDF…", CTA **and** "Gerar novamente" are disabled (symmetric locking — no interleaved regenerate/export state).
3. **Success receipt** (on success): `role="status"` green clear-line — "PDF exportado e verificado — {filename}" — where `{filename}` is the D-11 download name (`curriculo-{idioma}-{data}.pdf`). The browser download starts from the same response's PDF bytes.
4. **Self-check panel** (D-14) — a bare section mirroring the `KeywordsPanel` structure (title → summary → grouped chips), NOT a new card style. Blocks:
   - Title `h3` "Verificação ATS do PDF".
   - **Ordem das seções** — block label, then one row per exported section in extracted order: a leading "Contato no topo" row, then one `✓ {seção}` row per canonical heading in expected order (Resumo → Experiência → Formação → Habilidades → Certificações → Idiomas → Projetos — only sections actually present in the document; zero-entry passthrough sections are hidden exactly as in the card). `✓` green / `✗` red, glyph `aria-hidden`, row text always visible. Row labels are PT-BR UI-language constants (reuse `PREVIEW_SECTIONS` values + a new Contato label); an unknown section id renders its raw id — never silently dropped.
   - **Sobrevivência de keywords** (D-15) — block label, then the plain factual tally line (singular/plural), then chips reusing the **exact Phase 3 chip classes and semantics**: grouped by fixed `CATEGORY_ORDER`, empty categories hidden, `flex-wrap` only; `✓` green chip for a keyword that survived into the PDF text, `○` **gray** chip for one that did not — absence is honest information, not failure (Phase 3 rationale carries verbatim). Run-language keyword display (`pt`/`en`, canonical fallback) mirrors `KeywordsPanel`. Never a percentage or score.
   - Gate footer — one muted line stating what the automatic gate proved before the download was allowed (co-ocorrência empresa+cargo+datas, acentos intactos): the panel shows section order + survival; the gate footer makes the invisible server-side checks (D-06/D-07) visible as a guarantee.
   - Zero keywords extracted in the run → loud zero line: "Nenhuma keyword foi extraída nesta execução — nada para verificar no PDF." (the order block still renders).

**Gate failure (D-08) — export rejected:** the red error panel (ErrorPanel pattern) renders in Zone 6 under the CTA: title "Não foi possível exportar o PDF", backend PT-BR lines rendered **verbatim** (each names the failed verification — house D-13/D-14 division of labor), hint pointing to the terminal for raw detail. No file is delivered. **No separate retry button** — the "Exportar PDF" CTA directly above is the retry path (adding a second button for the same action would be clutter). Any previously rendered success receipt + self-check panel stays mounted — a failure never blanks prior state (Phase 3 principle). A fetch-level failure (server down) uses the same panel with the generic hint (the `erros=[]` convention from Phase 3).

**Interaction rules:**

| Rule | Contract |
|------|----------|
| Visibility | Zone 6 renders only when a result is mounted (`resultado !== null`) — same condition as Zones 4/5 |
| Export CTA enabled | `resultado` mounted AND `!exportPending` AND `!gerar.isPending` (disabled while the displayed resume is being replaced) |
| "Gerar novamente" while exporting | Disabled (`exportPending` locks it) — one long operation at a time |
| Regeneration resets export state | A new result clears the success receipt + self-check panel (the exported PDF no longer matches the displayed resume); the CTA remains for the new result |
| JD/language edits after export | Export zone stays valid untouched — D-10 exports exactly the displayed mounted state, which edits alone don't change |
| Ephemerality (D-16) | Self-check results live in session state only — page refresh loses them (the downloaded PDF file itself persists on disk; the panel does not) |
| One action, one request | Clicking Export triggers a single POST whose response carries the PDF bytes (→ blob download, D-11 filename) and the self-check payload (→ panel). `client.ts` gains a blob-path export with binary response handling (flagged in CONTEXT) — native fetch, no new deps |
| Transport | Exact endpoint contract (bytes vs multipart vs base64 envelope) is planner discretion (CONTEXT); this contract pins only the two UI effects above |

**State machine extension:** `result` (Phase 3) → `exporting` (controls locked, hint line) → `result+checked` (receipt + panel) or `result+export-error` (red panel; prior checked state preserved). Refresh returns to `result` without export state (D-16).

**Visual anchor per state** (Dimension 2): pre-export — the result card is the anchor with the blue "Exportar PDF" as the focal point beneath it; `exporting` — disabled CTA with the in-flight hint; `result+checked` — the self-check panel's green ✓ rows join the anchor group under the card; `export-error` — the red panel is the attention point under the CTA, with any prior checked state intact.

### Component conventions (new controls only — existing pinned classes are reused verbatim, never redefined)

| Control | Classes |
|---------|---------|
| Export primary CTA | Reuse the Phase 3 primary button classes verbatim: `min-h-10 rounded-md bg-blue-600 px-4 py-2 text-sm font-semibold text-white hover:bg-blue-700 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600 disabled:cursor-not-allowed disabled:opacity-50` |
| Export caption | `mt-2 text-xs text-gray-500` |
| Success receipt | `role="status"` + `rounded-md border border-green-200 bg-green-50 px-4 py-3 text-sm text-green-700` (lint clear-line pattern) |
| Export error panel | ErrorPanel structure verbatim: `rounded-md border border-red-300 bg-red-50 px-4 py-3`, title `font-semibold text-red-700`, lines `mt-2 list-disc pl-5 text-sm text-red-700 whitespace-pre-wrap`, hint `mt-3 text-xs text-red-600` |
| Self-check panel title | `text-base font-semibold text-gray-900` (KeywordsPanel title pattern) |
| Block label (Ordem das seções / Sobrevivência de keywords) | `mt-4 text-sm font-semibold text-gray-900` (form-label pattern) |
| Order row (✓) | `text-sm text-gray-700` with `aria-hidden` `✓` in `text-green-700` |
| Order row (✗) | Same row, `aria-hidden` `✗` in `text-red-700` |
| Survival chip (survived) | Verbatim Phase 3: `rounded-full border border-green-200 bg-green-50 px-2 py-1 text-xs text-green-700` + `✓` glyph + `sr-only` "no PDF" |
| Survival chip (absent) | Verbatim Phase 3: `rounded-full border border-gray-200 bg-gray-50 px-2 py-1 text-xs text-gray-500` + `○` glyph + `sr-only` "ausente no PDF" |
| Category sublabel | `text-xs text-gray-500` (KeywordsPanel verbatim) |
| Gate footer | `mt-4 text-xs text-gray-500` |

Accessibility baseline (unchanged): `focus-visible` rings on every control; status never conveyed by glyph or color alone; export feedback lives inside the existing `aria-live="polite"` region; all content renders as JSX text children — no raw-HTML injection path (T-01-08 posture).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline spacing (`gap-1`, `mt-1`) |
| sm | 8px | Compact element spacing (`gap-2`, chip padding) |
| md | 16px | Default element spacing, card padding (`gap-4`, `p-4`, `space-y-4`) |
| lg | 24px | Section padding, zone stacking (`px-6`, `space-y-6`) |
| xl | 32px | Layout gaps (`p-8`) |
| 2xl | 48px | Major section breaks (`py-12`) |
| 3xl | 64px | Page-level spacing (`py-16`) |

Exceptions (unchanged from the approved Phase 3 scale): 12px (`mt-3`, `px-3`) and 20px (`py-5`) — both multiples of 4, already shipped in Phase 1/3 components this phase reuses. Page frame stays `max-w-3xl mx-auto px-4`. No new exceptions in Phase 4.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 (Tailwind default on prose; panel rows and summaries) |
| Label | 12px (`text-xs`) | 400 | 1.5 (caption, gate footer, category sublabels, chips) |
| Heading | 16px (`text-base`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) — self-check panel title, block labels use Heading size at Label role |
| Display | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) — unchanged page heading |

Exactly 4 sizes (12/14/16/20) and 2 weights (400/600) for all new Phase 4 UI.

**Grandfathered patterns** (reused verbatim from Phases 1/3 — intentional consistency, not drift; do not "fix"): the result card's `text-2xl font-bold` name, `text-sm font-bold uppercase` section headings, `font-medium` (500) emphasis. Phase 4 introduces **no new** grandfathered patterns — every new string uses the contract values above.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fafb` (gray-50) | Page background (unchanged) |
| Secondary (30%) | `#ffffff` (white) + `#e5e7eb` (gray-200) borders | Cards, header bar, result card (unchanged) |

| Destructive / error | `#b91c1c` (red-700) on `#fef2f2` (red-50), border red-300 | Export gate-failure panel and ✗ order rows only |

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Export zone (no export yet) | ✅ covered | Only the CTA + expectation caption render — no ghost panel; the self-check panel exists only after a successful export (D-13) |
| empty | Survival checklist (zero keywords extracted in the run) | ✅ covered | Loud zero line — never a silent empty div; the order block still renders (the document always has contact + sections) |
| loading | Export CTA (media) | ✅ covered | Label swap "Exportando PDF…" + disabled + hint in the aria-live region; "Gerar novamente" locked symmetrically |
| error | Gate failure on export (media) | ✅ covered | Red panel with backend PT-BR lines verbatim naming the failed check; no file delivered (D-08); any prior receipt + panel stays mounted — failure never blanks prior state |
| error | Fetch-level failure (server down) | ✅ covered | Same panel with the generic hint (Phase 3 `erros=[]` convention); raw detail terminal-only |
| partial | Self-check results (media) | ✅ covered | Mixed ✓/✗ order rows and mixed ✓/○ chips render per-item verdicts — never masked to all-ok |
| populated | Self-check panel (list-collection) | ✅ covered | Order rows in extracted order (contact first); chips grouped by fixed CATEGORY_ORDER, empty categories hidden |
| overflow | Survival chips (list-collection) | ✅ covered | `flex-wrap` only; panel grows vertically, never horizontal scroll, never a table |
| long-text | Keyword chip terms (list-collection) | ✅ covered | Long terms wrap; chips wrap as flex items (Phase 3 behavior carried verbatim) |
| long-text | Filename in success receipt (static-content) | ✅ covered | Renders as plain wrapped text, no truncation |
| zero-one-many | Survival summary (list-collection) | ✅ covered | Singular/plural via a pure copy function (mirrors `resumoCoberturaCopy`; offline unit-testable per project test policy) |
| zero-one-many | Order rows | ✅ covered | One row per present section — the all-or-nothing envelope guarantees contact + at least the 3 generated sections, so the block never renders empty |
| populated | Both checklists at high volume (list-collection) | ✅ covered | Coverage panel and self-check panel each wrap 30+ keywords as chip grids — page grows vertically |
| overflow | Full checked page height (layout) | 🧪 backstop | Visual check at verify: result card + export zone + both checklists fully rendered (a JD rich enough for 30+ keywords) keeps the page readable — no cramping, zones clearly separated |
