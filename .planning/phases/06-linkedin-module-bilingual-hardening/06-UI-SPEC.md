# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 utility components (established Phase 1, extended Phases 3–5) |
| Icon library | none — unicode text glyphs only (✓ ✗ ○ ⚠), always `aria-hidden` and paired with a text label |
| Font | System UI stack (Tailwind default; no custom font loaded) |

**Decision (re-affirms the approved Phase 3/4/5 gate):** no shadcn/radix. STACK.md pins a deliberately lean stack (native fetch, no extra UI deps) and the app ships a coherent hand-rolled component set on plain Tailwind v4. Phase 6 adds ONE new page that mirrors the Currículo screen pattern plus one new report block — a component library would diverge from the established visual base for zero gain. Resolved `Tool: none` without re-asking (autonomous session; prior approved specs resolved this exact gate).

**Panels, not modals (re-affirmed):** no modal dialogs, no `window.confirm`, no toasts. Copy feedback, over-limit flags, QA warnings, and confirm strips all render as inline blocks in the page flow — the established pattern. The clipboard interaction is `navigator.clipboard.writeText` (D-08) with in-place label feedback, never a browser dialog.

**Scope fence:** Phase 6 touches the nav (`NAV_ITEMS` LinkedIn item → `enabled: true`, `App.tsx` view union gains `'linkedin'`), and adds one new page (`LinkedInHome`). The Currículo and Perfil screens are otherwise unchanged. Page frame stays `max-w-3xl mx-auto px-4` with the `space-y-6` rhythm.

## Screen Structure & Interaction Flow

One new screen: **LinkedIn** (D-01 — the disabled nav placeholder in `constants/ui.ts` becomes the third view; `App.tsx` view switch gains `'linkedin'`; landing stays Currículo). The page mirrors the Currículo pattern: objetivo → idioma → avisos → gerar → resultado (D-02/D-03/D-04), plus the phase-new QA report.

**Profile gate (identical to CurriculoHome):** same `['perfil']` query — pending renders `PERFIL_LOADING`; fetch failure renders `PERFIL_ERROR_TITLE`; broken profile renders `StatusLine ok={false}` + `ErrorPanel` (backend lines verbatim). A broken profile blocks generation on this page too.

### Zone 1 — form card (CARD_CLASSES pattern)

1. **Objetivo textarea** — visible label `Objetivo de carreira` (`text-sm font-semibold text-gray-900`), `TEXTAREA_CLASSES` verbatim, placeholder `Ex.: crescer como engenheiro de dados sênior, com foco em Python, SQL e plataformas de dados em nuvem…`. Client cap `LINKEDIN_OBJETIVO_MAX_CHARS` (WR-01 client mirror of the backend bound — planner/research fixes the value; mechanism pinned: cap states itself with a muted hint instead of a dead-end 422). Below-min hint (visible while trimmed length < min): `Descreva seu objetivo (mínimo {min} caracteres) para habilitar a geração.` — `LINKEDIN_OBJETIVO_MIN_CHARS` mirrors the JD's 80-char gate (D-02; exact value verified at planning).
2. **Idioma segmented control** — the Currículo segmented control reused verbatim (same classes, same `Português (BR)` / `English` options); label `Idioma das seções`.
3. **Primary CTA — "Gerar seções LinkedIn"** (`PRIMARY_BUTTON_CLASSES` verbatim); enabled when trimmed objetivo ≥ min AND no long op pending AND no editor open. In-flight label `Gerando seções LinkedIn…`.

### Zone 2 — lint avisos (D-03, non-blocking)

Debounced 800ms query firing at ≥ min trimmed chars (the exact Phase 3 mechanism). LintPanel structure verbatim (title → list / green clear-line → hint) with LinkedIn-scoped copy: title `Lacunas do perfil para este objetivo`, clear line `Nenhum gap relevante encontrado para este objetivo.`, hint reused verbatim. Backend `avisos[]` lines render **verbatim** — no frontend per-line constants. Fetch-level failure renders the same red-panel convention as Currículo's lint (`CURRICULO_LINT_FETCH_ERRO` copy). Pending lint renders nothing — the form stays primary.

### Zones 3 — result card + QA panel

Card header `Seções LinkedIn geradas` + `Gerar novamente` compact secondary + the permanent policy line `⚠ Edições valem apenas para esta execução — atualizar a página descarta.` (verbatim `POLICY_EDICAO`). Above the card, the ephemeral notice (Currículo copy verbatim): `Este resultado existe apenas nesta página — atualizar ou fechar o navegador perde o conteúdo. Copie o que quiser guardar.`

One run generates ALL sections (D-04). The card holds **four blocks** in fixed order — Headline → Sobre → Experiência → Habilidades (D-09 stage set). Generated-section headings reuse the card's bordered-uppercase pattern (`text-sm font-bold uppercase tracking-wide text-gray-500`); UI labels are PT-BR even on EN runs (house convention): `Headline`, `Sobre`, `Experiência`, `Habilidades`.

**Block anatomy (Headline / Sobre / Habilidades):**

```
HEADLINE                                              [Badge: Gerado | Editado]
──────────────────────────────────────────────────────────────────────
Copiar · Editar seção · Comparar com o perfil · Versões (2) · Adicionar dica   [Regenerar seção]
[dica block — only when toggled open]
{content}
{count}/{limite} caracteres
[red over-limit flag — only when over]
[Comparação — only when toggled open]
[Versões anteriores — only when toggled open]
[red error panel — only after a failed regen]
[amber confirm strip — only while a confirm is pending]
```

- **Action row** (`mt-2 flex flex-wrap items-center gap-x-3 gap-y-2`, under the h4 border): `Copiar` (compact secondary, FIRST — the phase's deliverable action), then quiet controls `Editar seção` · `Comparar com o perfil` (swaps to `Ocultar comparação`) · `Versões` (`Versões ({count})` when > 0, disabled at 0) · `Adicionar dica` (swaps to `Ocultar dica`; reveals the labeled one-line input, `HINT_INPUT_CLASSES`, `DICA_MAX_CHARS` 500 client mirror), then `Regenerar seção` (compact secondary, trailing — in-flight `Regenerando {seção}…`).
- **Counter (D-06)** sits directly UNDER the content it counts: `mt-2 text-xs`, format `{count}/{limite} caracteres`. States: normal `text-gray-500`; ≥ 90 % of limit `text-amber-700`; over limit `text-red-700`.
- **Over-limit flag (D-07):** when the generated text exceeds the limit, a red line renders under the counter: `Passou do limite em {excesso} caracteres — regenere a seção ou edite o texto para caber.` Nothing is ever truncated; the flag + per-section regen are the fix path. `Copiar` stays enabled (it copies what is displayed; the flag warns, the user decides).
- **Skills counter exception (honest-information rule):** LinkedIn imposes no total character limit on the skills list, and D-05 forbids inventing unverified limits. The Habilidades block renders a count line in the counter slot instead: `1 skill em ordem de prioridade.` / `{n} skills em ordem de prioridade.` — no fake `/Y`. If research verifies a real per-skill or list bound, planner adds it via the same config-constant mechanism.

**Experiência group (D-09: one stage returns a map per company):** the group has ONE action row (`Comparar com o perfil` · `Versões` · `Adicionar dica` · `[Regenerar seção]` — the group is the regen unit, one stage call) and renders **one sub-block per profile experience**:

```
Empresa A — Cargo A                                          [Badge]
{descrição gerada — paragraphs}
{count}/{limite} caracteres   Copiar · Editar entrada
```

- Sub-block header: `text-sm font-semibold text-gray-900` company — title (profile-fact anchor, fixed — never editable), per-entry Badge (`Gerado`/`Editado` — entries are edited independently).
- Per-entry footer row: counter + `Copiar` + `Editar entrada` (quiet). **Copied text = that entry's description only** — company/title are NOT included (LinkedIn has separate fields for them; the copied block pastes straight into the description field).
- Group regen stacks every entry's current text first (D-14 stack-before-mutate), re-runs the one stage, and wholesale-swaps the group's entries — sibling blocks (Headline/Sobre/Habilidades) byte-identical.
- A profile with zero experiences renders a loud muted line in the group: `Nenhuma experiência no perfil — nada para reescrever aqui.` — never an empty block.

**Habilidades block:** content renders as an ordered list (`mt-2 list-decimal space-y-1 pl-5 text-sm`) — priority order IS the deliverable, so positions are visible. `Copiar` copies all skills one per line in priority order. Editing is one textarea, one skill per line (Phase 5 Habilidades granularity; save splits/trim/drops empties, `EDIT_SAVE_GUARD` on zero items).

**Editar (D-12 mechanism reused):** click-to-edit replaces the block content with a textarea (`TEXTAREA_CLASSES` verbatim, `maxLength` = the block's limit — D-05 client mirror), footer `Salvar alterações` · `Cancelar edição` + policy line. **Over-limit save guard:** `Salvar alterações` is disabled while the draft exceeds the limit, with hint `O texto excede o limite em {excesso} caracteres — reduza antes de salvar.` (WR-01 mirror of the server bounds — an oversized save must never become a dead-end 422). One editor at a time; dirty cancel routes through the amber ConfirmStrip; regen-over-edits and full-regen-with-edits reuse the Phase 5 strips and messages **verbatim**.

**Comparação com o perfil (Phase 5 pattern reused on all four blocks):** two-column panel, facts left / current text right (right-column header adapted: `Texto no LinkedIn`), deterministic amber `<mark>` suspicion highlights with the same `sr-only` suffix, legend adapted to this phase's deliverable: `… Confira você mesmo antes de copiar.` Facts column: Headline/Sobre → profile summary; Experiência → the matching entry's description + impacts (company fold-match, all-entries fallback note); Habilidades → profile skills grouped under category sublabels as plain text, never chips. Component reuse vs a LinkedIn-typed variant is planner discretion; the visual pattern is pinned.

**Versões (Phase 5 mechanism reused):** per block (Experiência: per entry), newest-first, origin badge + `Restaurar versão` + `line-clamp-2` snippet; restore stacks the current version first. Session state only, never capped, never silently dropped.

**QA panel — "Verificação de idioma" (D-13/D-14 — the phase's new UI surface).** Bare section directly below the result card (it verifies the artifact above it — the SelfCheckPanel role), never a new card style: title `h3` `text-base font-semibold text-gray-900`, block labels `mt-4 text-sm font-semibold text-gray-900`.

- **Glossário aplicado (D-13)** — one row per deterministic substitution: `{origem} → {preferido}` (`text-sm text-gray-700`, the arrow is plain text). Zero substitutions → loud zero line: `Nenhum termo do glossário foi aplicado — as seções já usavam os termos preferidos.`
- **Inglês em texto em português (D-14)** — one row per bleed finding: `{termo} — {seção}` (`text-sm text-amber-800`; amber = attention-without-failure, the established warning family). Zero findings → `Nenhum termo em inglês foi detectado nas seções em português.`
- **Legend (always, non-blocking framing):** `A verificação é mecânica e não bloqueia a cópia — termos técnicos consolidados em inglês podem ser sinalizados. Avalie você mesmo antes de copiar.` (`mt-4 text-xs text-gray-500`)
- **EN runs:** the QA is defined for PT-BR outputs (SC4); on EN runs the panel renders the neutral line `A verificação de idioma se aplica às saídas em PT-BR — esta execução gerou conteúdo em inglês.` — never silently absent.
- **Truthfulness rule:** the panel displays the LATEST generation response's QA payload — replaced wholesale on every generation success (full or per-section regen; both pass through post-gen glossary + QA, the D-07 coverage-refresh pattern). Edits/restores keep the last computed report (the Phase 5 coverage-snapshot precedent — the panel is advisory and its legend says so). Never a score, never a percentage.

### Interaction rules

| Rule | Contract |
|------|----------|
| Scope | New controls render only on the LinkedIn page; Currículo/Perfil untouched except the nav enable |
| CTA enabled | Trimmed objetivo ≥ min AND no long op pending AND no editor open |
| One long op at a time | While gerar or any regen is pending: CTA, `Gerar novamente`, every `Regenerar seção`, all edit controls, `Restaurar versão`, dica toggles/inputs disabled. `Comparar`/`Versões` toggles and every `Copiar` stay usable (read-only/instant — copying what is displayed is always safe) |
| One editor at a time | An open editor disables every edit affordance + the CTA + `Gerar novamente`; own-section regen routes through the D-14 strip; the editor's Salvar/Cancelar freeze during any flight (`locked`) |
| Over-limit handling | Red counter + flag line on display; editor maxLength blocks growth; `Salvar alterações` disabled while over with the reduce-first hint; per-section regen is the correction path; no automatic truncation anywhere (D-07) |
| QA truthfulness | QA panel swapped only by generation success (full or section); edits/restores keep the last report; EN runs render the neutral note |
| Badge lifecycle | `Gerado` at mount/regen · `Editado` on save or restore-of-edited — per block, per experiência entry |
| Version stacks | Per block (Experiência: per entry); stack-before-mutate on EVERY destructive path (edit save, regen success, restore, confirmed full regen) |
| Failure never blanks | A failed gerar keeps any prior result mounted; a failed section regen renders the red panel inside the owning block with prior text intact |
| Ephemerality (D-11) | All LinkedIn state is session React state; refresh returns to the empty form — stated permanently by the policy + ephemeral lines |

**State machine:** `idle → typing → in-flight → result` (QA panel mounted) with per-block sub-states `viewing ⇄ editing (→ dirty-cancel confirm)` · `viewing → regen-pending → viewing | regen-error → viewing` and two orthogonal disclosures per block (comparação, versões). Refresh returns to `idle` (D-11).

**Visual anchor per state:** idle/typing — the form card is the anchor with the blue CTA as focal point; in-flight — disabled CTA + the page-level hint line; result — the four-block card is the anchor, QA panel reads as its proof block below; over-limit — the red counter + flag mark the exact block; editing — the textarea + `Salvar alterações` are the block's local focus; regen-error — the red panel is the block's attention point with prior text intact.
