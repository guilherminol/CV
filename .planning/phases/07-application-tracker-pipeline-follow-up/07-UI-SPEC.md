## Layout & Screen Assembly

The house envelope is non-negotiable: `main` stays `mx-auto max-w-3xl px-4 py-6` (App.tsx:115) for the tracker like every other view. TrackerHome section order (07-03 Tasks 1+3, top to bottom), all inside `space-y-6`:

1. `h2` page title — `text-xl font-semibold text-gray-900` **[shipped 07-01]**
2. `ContadoresGrid` — replaces the 07-01 contadores `dl` (same visual: 3-column `grid grid-cols-3 gap-2`, tiles `rounded-md border border-gray-200 bg-gray-50 px-3 py-2`)
3. Visão geral — prazo-ordered candidatura list (payload order is already server-sorted: prazo proximity first, `null` prazo last — render in order, never re-sort client-side), each row carrying the prazo chip + follow-up badge
4. `KanbanBoard` — one column per stage in `estagios` ordem
5. Detail region — the one open `EventosPanel` + Arquivar/Reabrir control for the clicked candidatura
6. `CandidaturaForm` — "Nova candidatura" (create) or edit mode with "Salvar alterações"
7. `EstagioManager` — **collapsed by default**
8. Export section — "Exportar JSON" + "Exportar CSV"

Documented assumption A-UI-1 (kanban geometry): 5+ stage columns do not fit 768px, so the board is a `flex gap-2 overflow-x-auto pb-2` row of fixed-width columns (`w-48 shrink-0` = 192px). Horizontal scroll keeps the max-w-3xl shell intact; breaking the shell for one view is rejected as house-inconsistent.

## Interaction Contracts

**Kanban (D-14 — RESEARCH Pattern 5 verbatim; 07-03 Task 2):**
- One `DndContext` per board; `useSensors(PointerSensor with activationConstraint { distance: 8 })` — clicks stay clicks (Pitfall 4) — `+ KeyboardSensor({ coordinateGetter: sortableKeyboardCoordinates })`; `collisionDetection={closestCorners}`.
- One `SortableContext` per column; its `items` array derives from THE SAME filtered array `.map()` renders (Pitfall 10).
- Each column body is also a `useDroppable` target keyed by the stage id so an EMPTY column accepts drops.
- `CandidaturaCard` calls `useSortable({ id: candidatura.id })`, transforms via `CSS.Transform.toString(transform)` + `transition`; drag `listeners`/`attributes` attach to the card HEADER region only (the drag handle) — never to nested buttons; clicking the card body calls `onAbrir` (opens the detail region).
- `onDragEnd` resolves the target stage (over.id is a card → that card's `estagio_id`; a column droppable → that stage) then calls the mover mutation. **No optimistic update** (A8 pin): the card stays put until the refetch returns the truth.
- No `DragOverlay` this phase (columns/cards are small — optional polish rejected for scope).
- Keyboard DnD must work end-to-end (07-05 UAT covers it manually).

**Mutations & cache (first persistent view in the app):**
- Every successful tracker mutation (criar, editar/arquivar, mover, evento, followup executar/adiar, estágio CRUD) calls `queryClient.invalidateQueries({ queryKey: ['tracker'] })` (Pitfall 6) — kanban, overview, and contadores can never desynchronize.
- Envelope discipline: `status === 'ok'` clears `erros` and keeps the prior UI mounted; `status === 'erro'` renders `data.erros` verbatim via ErrorPanel and keeps the form/list mounted; fetch-level `onError` renders the generic PT-BR hint. Initial load uses `isPending` (never `isLoading` — Pitfall 9).
- Buttons disable while their mutation `isPending`; CTA label swaps to the inflight string.

**Server-derived rendering (D-07/D-09/D-11/D-12 posture):**
- The client renders `dias_para_prazo`, `sugerir_followup`, `followup_pendente`, `followup_vencido`, `atrasado_prazo`, and `contadores` verbatim from the payload — it NEVER recomputes, never parses deadlines with `new Date()` (grep-pinned: `grep -c "new Date(" frontend/src/components/tracker` = 0; Pitfall 7). Overview order comes from the payload.
- "Today" exists client-side only in the 07-04 association flow, built as a zero-padded local-parts string (getFullYear/getMonth/getDate) — never `toISOString()` (UTC drift).

**Form contract (D-06 — the 11 fields; 07-03 Task 1):**
- `empresa` (required, maxLength 200), `cargo` (required, maxLength 200), `fonte` (200), `link_vaga` (2000, `type="url"`), `data_aplicacao` + `prazo_retorno` (`type="date"`), `faixa_salarial` (100), `contato_recrutador` (200), `modalidade` (sr-only radio fieldset idiom — CandidaturaHome precedent — labels Remoto/Híbrido/Presencial from `RASTREADOR_MODALIDADE_LABELS`), `notas` (textarea, 5000), `jd_texto` (textarea, 20000).
- Every `maxLength` mirrors the backend `Field` bound in `backend/app/tracker/models.py` with a WR-01-style "Change BOTH together" comment — oversized input is prevented at the source, never retried into a dead-end 422. Bounds constants live in `constants/ui.ts` or the form module top, mirroring the shipped `EMPRESA_MAX_CHARS`/`CARGO_MAX_CHARS` **[shipped 07-01]**.
- Create submit gate: empresa + cargo trimmed non-empty (house minimum-field pattern **[shipped 07-01]**); `estagio_id` optional — when unset the server defaults to the first stage by `ordem` (07-01 pin), so the form default-selects the first payload stage.
- EventosPanel registro form: tipo select (the five literals' PT-BR labels), `data_evento` date input, idioma select ("—"/pt-BR/en, reusing `CURRICULO_IDIOMA_OPTIONS` labels), observação (maxLength 2000).
- Adiar date input must target a future date — the server rejects past targets; the UI sends the picked string and renders the PT-BR erro envelope if refused.

**Detail region:** one candidatura detail open at a time (house "one editor at a time" convention) — clicking a card swaps the region's content; the region shows `EventosPanel` (event list + registro + follow-up controls), `link_vaga` as a plain anchor with `rel="noreferrer"` (only place the link renders), nullable detail fields as a muted "—" (documented assumption A-UI-2: aligned field grid, loud null), and the Arquivar/Reabrir control.

**Rendering & accessibility posture (S10/S6):**
- ALL tracker text renders exclusively as JSX text children — `dangerouslySetInnerHTML` is forbidden (grep-pinned). `link_vaga` is the only anchor.
- Status is never color-alone: sr-only suffixes on chips; radio fieldsets use the sr-only-input idiom with visible labels; sections use `aria-labelledby`; every interactive element carries `focus-visible` outline utilities (house constants already do).
- Empty columns, empty lists, and zero counters are loud (documented strings above) — never silently blank.
